# CMT Intelligence OS v1.1 — نسخه آزمایشی یکپارچه، نه محصول تجاری تأییدشده

**تاریخ:** 2026-10-25

نسخه 1.0 شامل تمام قابلیت‌های نسخه 0.9 و مسیر کنترل کیفیت، خروجی مستقل CSV، ابزار پشتیبان‌گیری قابل بررسی و ارزیابی مستقل استخراج اطلاعات است. ۱۵ گردش‌کار آزمایشی/بازرسی در نمایشگر آفلاین محفوظ هستند. هیچ رکوردی به‌طور خودکار پذیرفته یا به عنوان گواهی رسمی صادر نمی‌شود.

## دو شیوه اجرا

**نمایش بدون سرور**: فایل `index.html` را در Chrome یا مرورگر دسکتاپ باز کنید. بخش‌های ثبت آزمایش، منحنی Proctor، الک‌ها، سیلندرها و شواهد مصنوعی قابل نمایش هستند؛ تب `11 · Secure pilot` برای ورود/ثبت رکورد سمت سرور کار نمی‌کند.

**پایلوت محلی با سرور** (توسعه‌دهنده، Python 3.11+):

```bash
python -m venv .venv
source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m server.pilot create-user --username fieldtech --role technician
python -m server.pilot create-user --username reviewer --role engineer
python -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```

به `http://127.0.0.1:8000` بروید. کاربران را با رمز متفاوت و طولانی ایجاد کنید. **کاربر و رمز پیش‌فرض وجود ندارد.** حساب‌های مهندس و تکنسین باید متعلق به افراد متفاوت باشند. اطلاعات شرکت یا مشتری را بدون مجوز کتبی وارد نکنید. رابط آفلاین و دیتابیس پایلوت دو مخزن مستقل‌اند.

### مسیر نمونه با داده ساختگی

۱. در تب 11 وارد حساب تکنسین شوید. نمونه خاک `{"wet":126,"moisture":11.8,"mdd":120,"minComp":95}` را ببینید؛ نام پروژه و مرجع دستگاه و مشخصات ساختگی هستند.

۲. چک‌باکس اختیار ثبت داده را بزنید. گزینه **Check entered fields** هشدار پایین‌تر بودن تراکم محاسباتی از حد نمونه پروژه را نمایش می‌دهد؛ این هشدار به معنی اعلام مردودی رسمی نیست.

۳. **Create server draft** و **Submit for engineer review** را بزنید. داده ناقص، غیرمنطقی، واحدهای متعارض یا نبود شواهد لازم در پروفایل‌های اصلی مانع ارسال می‌شود. رفع اشکال باعث ایجاد نسخه اصلاح‌شده می‌شود.

۴. خارج شوید و با حساب مهندس وارد شوید. بررسی انسانی را با توضیح ثبت کنید. ثبت `reviewed` فقط علامت انجام بررسی است؛ نه امضای حرفه‌ای یا پذیرش مصالح.

۵. مهندس می‌تواند `Export neutral CSV` بگیرد. این خروجی vendor-neutral است و **اتصال مستقیم به ElmTree یا نرم‌افزار GET نیست**. داده‌ها پیش از خروجی با تاریخچه هش بررسی می‌شوند. حروف شروع‌کننده فرمول در سلول‌های متنی خنثی می‌شوند.

## نسخه پشتیبان آزمایشی، با کنترل صحت

مسیر پیش‌فرض SQLite: `~/.cmt_intelligence_os/pilot.sqlite3`، قابل تغییر با `CMT_PILOT_DB`.

```bash
python -m server.backup backup ./CMT_snapshot_001.sqlite3
python -m server.backup verify ./CMT_snapshot_001.sqlite3
```

ابزار بک‌آپ از `sqlite3.backup` استفاده می‌کند، دستورالعمل `PRAGMA integrity_check` و زنجیره رویدادها را بررسی می‌کند و فایل قبلی را بازنویسی نمی‌کند. **بازگردانی، نگهداری خارج‌از‌سایت، رمزگذاری داده‌ها و بازیابی پس از فاجعه هنوز استقرار و آزمون عملیاتی نشده‌اند.** فایل SQLite را محرمانه نگه دارید و با مجوزهای محدود حفاظت کنید.

## آزمون بی‌طرفانه دقت استخراج و زمان

ورودی نمونه فقط ساختگی است. با فایل‌های دارای برچسب مرجع انسانی قابل تعویض است، اما پیش از استفاده واقعی باید مجوز سازمانی و ناشناس‌سازی وجود داشته باشد.

```bash
python validation/pilot_benchmark.py examples/SYNTHETIC_LABELLED_BENCHMARK.csv --json-out ./synthetic_benchmark_report.json
```

این ابزار دقت هر فیلد، خطا/خودداری در فیلدهای حساس، فاصله Wilson 95% و مجموع زمان دستی در برابر مجموع زمان نرم‌افزار **به‌اضافه بازبینی و اصلاح** را محاسبه می‌کند. داده‌های مصنوعی و مجاز واقعی در گزارش جدا هستند؛ از ۸ ردیف ساختگی هیچ ادعایی درباره شرکت GET یا دقت مدل OCR واقعی نتیجه نمی‌شود.

## آزمایش‌های پیاده‌سازی‌شده

- خاک: NDG، رطوبت، حدود اتربرگ، پروکتور خلاصه، سندکون، منحنی چندنقطه‌ای پروکتور
- بتن: اسلامپ/هوا/دما، سیلندر تکی، وزن مخصوص بتن تازه، مجموعه سیلندرهای هم‌سن
- سنگدانه: کنترل یک الک و دانه‌بندی سری الک
- آسفالت: وزن مخصوص مغزه، درصد فضای خالی
- بازرسی: کاور میلگرد

**تفاوت کنترل ورودی با اجرای کامل استاندارد:** فرمول‌های نمونه و کنترل محدوده‌های کاربر-تعریف‌شده جایگزین الزامات مجاز و نسخه جاری ASTM/AASHTO، تصحیحات تجهیزات، نمونه‌برداری، کالیبراسیون، کیفیت نمونه و قضاوت مسئول فنی نمی‌شوند.

## آزمون‌ها

```bash
PYTHONPATH=. python -m pytest -q
python validation/reference_oracle.py
```

۶۹ تست خودکار شامل API، مرورگر، QA، نقش‌ها، کنترل دست‌کاری، CSV و پشتیبان‌گیری. تست‌ها گواهی امنیت یا استاندارد مهندسی نیستند.

## مانع‌های مشخص عرضه تجاری

- پایلوت مجاز با فرم‌های واقعیِ ناشناس‌شده و برچسب‌گذاری دو نفره، شامل نمونه‌های دشوار و ناکامی خواندن
- قفل کردن روش‌ها/دقت/گردکردن بر اساس نسخه مشخص مجاز استاندارد و مشخصات پروژه و امضای مسئول فنی
- معماری تولید: HTTPS/TLS، هویت شرکتی و MFA، محدودسازی ورود، رمزگذاری داده در حالت سکون، بک‌آپ و بازگردانی قابل اثبات، پایش رخدادها، جداسازی مشتریان، امضای مناسب و حسابرسی بیرونی
- اتصال تأییدشده به LIMS موجود؛ نام نرم‌افزار مورد استفاده GET هنوز قطعی نیست
- آزمایش عملکرد و ارزش اقتصادی روی کار واقعیِ مجاز و مقایسه آماری بی‌طرفانه

**به شرکت GET یا تجهیزات هسته‌ای NDG وصل نشده است. داده آزمایش‌ها صرفاً نمونه‌های مصنوعی هستند.**


## افزوده‌های نسخه 1.1

- **QA برای همه ۱۵ دسته:** حداقل فیلدهای لازم و کنترل‌های عددی برای هر دسته؛ هیچ روش ناآشنا بدون پروفایلِ کنترل، قابل ارسال نیست. خروجی همچنان تنها برای بازبینی مهندس است.
- **گزارش هر رکورد:** در تب `11 · Secure pilot` روی رکورد کلیک کرده و `Download selected review worksheet (JSON)` را بزنید. برای بررسی checksum روی فایل دانلودی:

```bash
python -m server.report_verify ./CMT_UNCERTIFIED_record.json
```

- **آزمایش بازیابی:** بعد از ایجاد فایل snapshot با دستور backup زیر، فقط در یک مسیر جدید بازیابی کنید:

```bash
python -m server.backup backup ./snapshot.sqlite3
python -m server.backup restore-test ./snapshot.sqlite3 ./restored_test.sqlite3
python -m server.backup verify ./restored_test.sqlite3
```

این کار دیتابیس اصلی را بازنویسی نمی‌کند. فایل‌های SQLite و خروجی گزارش ممکن است اطلاعات حساس داشته باشند؛ فقط داده ساختگی یا مجاز و غیرمحرمانه استفاده کنید.

- **کنترل ورود محلی:** پنج تلاش ناموفق برای یک username در کمتر از ۱۵ دقیقه ورود را برای ۱۵ دقیقه متوقف می‌کند. هیچ MFA/SSO یا بازیابی حساب شرکتی وجود ندارد.

- **نمونه‌های همه ۱۵ دسته:** فایل `examples/SYNTHETIC_ALL_15_QA_PROFILES.json` کاملاً ساختگی است.

برای فهرست دقیق کارهای انجام‌شده و موانع تجاری‌سازی `RELEASE_NOTES_FA.md` را بخوانید.
