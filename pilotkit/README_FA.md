# بسته شواهد پایلوت CMT — نسخه 1.6

این ابزار **آفلاین** است و برای بازبینی اولیه اطلاعات آزمایش‌ها ساخته شده است. به نرم‌افزار ElmTree، حساب شرکت، یا API خارجی متصل نمی‌شود.

## کاربرد

۱. دو نسخه مستقل از اطلاعات NDG یا بتن تازه را با داده‌های *تایپ‌شده/بازخوانی‌شده توسط انسان* دریافت می‌کند. این ابزار خودش عکس را OCR نمی‌کند.
۲. اختلاف اعداد، تبدیل واحدها و مغایرت شناسه پروژه یا آزمایش را بررسی می‌کند.
۳. موارد تکراری را بدون حدس‌زدن قرنطینه می‌کند.
۴. گزارش HTML مناسب مدیر، صف رسیدگی CSV برای مهندس، JSON نتایج و هش SHA-256 در ZIP تولید می‌کند.
۵. کنترل صحت ZIP را انجام می‌دهد؛ هش **امضای رسمی یا تضمین اصالت منبع نیست**.

## روش اجرا

در کامپیوتری با Python و وابستگی‌های پروژه، از پوشه اصلی دستورهای زیر را اجرا کنید:

```bash
python -m pilotkit.batch build --input pilotkit/examples/SYNTHETIC_BATCH_V16.json --output CMT_Synthetic_Review_Bundle.zip --synthetic-demo
python -m pilotkit.batch verify --bundle CMT_Synthetic_Review_Bundle.zip
```

پس از استخراج ZIP، فایل `summary.html` را باز کنید. تمام نمونه‌های آماده ساختگی هستند.

## استفاده از اطلاعات واقعی

**تا دریافت مجوز مکتوب و ضوابط امنیتی شرکت، از اطلاعات GET، گزارش واقعی، فایل مشتری، تصویر پروژه یا مشخصات شخصی استفاده نکنید.** پس از دریافت مجوز، صرفاً با داده‌های بدون مشخصات محرمانه و در محیط تأییدشده می‌توان از گزینه `--authorized-data` استفاده کرد. این گزینه، خودِ مجوز را راستی‌آزمایی نمی‌کند و هیچ داده‌ای نباید در GitHub عمومی منتشر شود.

## نقاطی که هنوز تکمیل نشده

- دقت OCR/AI روی فرم‌های واقعی اندازه‌گیری نشده
- قالب رسمی Import یا API سازنده ElmTree تأیید نشده
- نتیجه این بررسی، Pass/Fail مصالح، تأیید مهندس یا انطباق ASTM/AASHTO نیست
- سخت‌گیری لازم برای بهره‌برداری سازمانی، مدیریت داده محرمانه و امنیت هنوز باید جداگانه بررسی شود

برای یک پایلوت واقعی، از مدیر بخواهید ابتدا استفاده از ۲۰ تا ۳۰ فرم ناشناس‌شده را به‌شکل رسمی تأیید کند و زمان ورود دستی، زمان اصلاح خطا و کیفیت بازبینی را با روش موجود مقایسه کند.
