# CMT Intelligence OS — v1.2 (Engineering evidence, AI evaluation & deployment safety)

**وضعیت محصول:** نمونه تحقیق و پایلوت محلی. **محصول تجاری آماده استقرار نیست.** تاریخ: 25 اکتبر 2026.

## خلاصه تغییرات قابل اثبات

- ۱۵ نوع آزمایش از نسخه‌های گذشته؛ ۶۹ تست قبلی حفظ شده و ۲۰ تست جدید برای مراحل بحرانی اضافه شده: **۸۹ تست موفق**.
- **دروازه اعتبارسنجی روش:** ماتریس برای تک‌تک ۱۵ نوع آزمایش، با نسخه مشخص روش، مشخصات پروژه، گزارش مقایسه و تأیید مسئول فنی. تا وقتی این شواهد وارد و مستقل بررسی نشوند، نتیجه BLOCKED است. ورود دستی `approved` خود به خود اعتبار رسمی ایجاد نمی‌کند.
- **برچسب‌گذاری دو نفره:** هر فیلد باید توسط دو شخص متفاوت از روی سند اصلی جداگانه خوانده شود؛ اختلاف با بازبین سوم حل شود. در غیر این صورت خروجی ارزیابی ساخته نمی‌شود. داده‌های ساختگی از واقعی جدا هستند.
- **سنجش عملکرد:** ابزار موجود `pilot_benchmark.py` دقت، خطای فیلد بحرانی، فاصله اطمینان Wilson و زمان دستی در برابر مجموع زمان AI، بررسی و اصلاح را گزارش می‌کند. آستانه‌های گیت داخلی برای پایلوت/محصول نمونه‌اند، قانون ASTM نیستند.
- **سخت‌گیری سمت سرور:** کنترل Host برای کاهش ریسک DNS rebinding، رد سریع `Content-Length` بزرگ و کوکی Secure روی اتصال HTTPS. این‌ها به تنهایی امنیت شبکه یا استقرار عمومی را کامل نمی‌کنند.
- **Preflight محلی:** وجود دیتابیس، مجوزهای فایل، سازگاری تاریخچه و حساب‌های جداگانه را گزارش می‌کند؛ به‌طور صریح آماده‌بودن محصول برای تولید را نفی می‌کند.

## شروع سریع نسخه آفلاین

فایل `index.html` را در مرورگر دسکتاپ باز کنید. فرم‌ها، نمودارها و گردش‌کارهای آزمایشی قبلی کار می‌کنند. برای **Secure pilot** باید سرور محلی نسخه قبل مطابق `README_FA.md` اجرا شود. از عکس/فایل یا داده واقعی GET بدون مجوز استفاده نکنید.

## مسیر دقیق سنجش AI (کاملاً آفلاین)

۱. قالب `validation/SYNTHETIC_TWO_LABELERS.csv` را بردارید؛ برای هر فیلد از مدرک **مجاز و ناشناس‌شده** مقادیر را با دو نفر مستقل ثبت کنید. ستون `source` باید `authorized` باشد، اما همین برچسب بدون بررسی مجوز کفایت نمی‌کند.

۲. اگر دو نظر متفاوت بود، نفر سوم که مستقل از دو برچسب‌گذار است در `adjudicated` مقدار نهایی را ثبت کند. سپس:

```bash
python validation/label_reconcile.py validation/SYNTHETIC_TWO_LABELERS.csv --out ./consensus.csv --manifest ./labels_manifest.json
python validation/pilot_benchmark.py ./consensus.csv --json-out ./pilot_metrics.json
```

این دو فرمان روی نمونه‌های ساختگی فقط گردش‌کار را نمایش می‌دهند؛ **آزمایش زنده AI نیستند.** برای آزمون مدل واقعی باید `predicted` از OCR اجراشده با اجازه رسمی روی عکس‌ها پر شود، نه از دستیابی به مقدار طلایی. برچسب‌گذاران باید تا حد امکان نسبت به خروجی AI نابینا باشند.

۳. در صورت اختلاف حل‌نشده، برنامه `label_reconcile.py` با خطا متوقف می‌شود و هیچ فایل اجماعِ ناقص تولید نمی‌کند.

## ماتریس استانداردها و گیت انتشار

برای هر روش، نسخه استاندارد *دارای مجوز*، ارجاع مشخصات پروژه، مرجع شواهدِ آزمایشگاه (SHA256 فایل شواهد)، نام/تاریخ بازبین را پس از تأیید واقعی وارد `METHOD_APPROVAL_MATRIX_PENDING.csv` کنید. ۱۵ ردیف باید بررسی شوند؛ برای یک روش مثل Proctor، نمونه‌های «چگالی ماکزیمم» و «منحنی چندنقطه‌ای» هر دو باید دامنه روش‌شان روشن باشد.

در `SECURITY_EVIDENCE_PENDING.json` نیز کنترل‌ها باید پس از تأیید مستقل و دریافت مستند واقعی وارد شوند؛ در نسخه آزمایشی همه `pending` هستند.

```bash
PYTHONPATH=. python -m validation.release_gate \
  --methods validation/METHOD_APPROVAL_MATRIX_PENDING.csv \
  --benchmark examples/SYNTHETIC_LABELLED_BENCHMARK.csv \
  --security validation/SECURITY_EVIDENCE_PENDING.json \
  --out ./gate_report.json
```

این دستور با اطلاعات فعلی **BLOCKED** و کد خروج ۲ برمی‌گرداند (رفتار صحیح). حتی اگر تمام شواهد تکمیل شوند، نتیجه نهایی فقط `EVIDENCE_REVIEW_REQUIRED` خواهد بود؛ انتشار نیازمند ممیزی، مجوزها، تصمیم مهندس مسئول و قرارداد مشتری است.

آستانه‌های پیش‌فرض داخلی گیت: ۲۰۰ فیلد مجاز، حداقل ۱۰۰ فیلد بحرانی، صفر خطا/خودداری بحرانی، حداقل ۹۸٪ تطبیق فیلد و زمان خالص مثبت؛ این‌ها **اهداف پیشنهادی نمونه‌اند و باید با ریسک آزمایش توسط تیم فنی بازتعریف شوند، نه معیار رسمی ASTM.** در حالت انتشار جامع، همه ۱۵ نوع آزمایش باید داده ارزیابی داشته باشند.

## گزارش امنیت محلی

```bash
PYTHONPATH=. python -m server.preflight
```

بدون دیتابیس محلی پیغام نبود دیتابیس صحیح است. اگر دیتابیس را با کاربران پایلوت ساختید، بررسی نقش‌ها و تاریخچه اجرا می‌شود. تست جدید DNS rebinding روی مسیر API انجام شده؛ با این حال محدودیت اندازه فقط `Content-Length` اعلام‌شده را پیش از خواندن کنترل می‌کند و در استقرار تولید باید روی reverse proxy و ASGI هم سقف جریان اعمال شود.

**پایانِ سه مانع هنوز مشروط به شواهد بیرونی است:**

1. **مهندسی:** آزمایشگاه صاحب مجوز استانداردها، گزارش‌های مستقل آزمون و تأیید مسئول فنی برای ۱۵ گروه؛ الان فاقد این شواهد هستیم.
2. **AI/اقتصاد:** مجموعه فرم‌های واقعی ناشناس‌شده با مجوز، برچسب انسانی مستقل، خروجی مدل واقعی و زمان‌سنجی زوجی؛ الان فقط داده ساختگی داریم.
3. **امنیت/اتصال:** احراز هویت سازمانی و MFA، TLS، رمزگذاری و مدیریت کلید، پشتیبان رمزگذاری‌شده و بازیابی اثبات‌شده، پایش، جداسازی داده مشتری و بازبینی امنیت بیرونی؛ اتصال به نرم‌افزار واقعی GET نیازمند تعیین نرم‌افزار و اجازه اتصال است.

هر زمان هر سه مورد شواهد واقعی فراهم شد، گیت به‌جای ادعای آماده‌بودن، پرونده را برای تأیید نهایی انسان آماده می‌کند.

## نقطه کنترل امضاشده (جدید در این نسخه)

برای آزمایشگاه محلی، می‌توان یک کپی قابل راستی‌آزمایی از وضعیت زنجیره حسابرسی امضا کرد؛ کلید خصوصی با گذرواژه رمزگذاری می‌شود و باید **جدا از دیتابیس** نگهداری شود. نیازمند پکیج `cryptography` در `requirements.txt` است.

```bash
# برای ساخت کلید، مسیرهای خارج از پوشه دیتابیس انتخاب کنید:
PYTHONPATH=. python -m server.audit_anchor create-key ./KEY_PRIVATE.pem ./KEY_PUBLIC.pem
# با گذرواژه کلید، یک نقطه کنترل امضا شده و جدا از دیتابیس صادر کنید:
PYTHONPATH=. python -m server.audit_anchor sign ./KEY_PRIVATE.pem ./checkpoint.json
# فایل عمومی و نقطه کنترل را در فضای مستقل و با دسترسی محدود بایگانی کنید:
PYTHONPATH=. python -m server.audit_anchor verify ./KEY_PUBLIC.pem ./checkpoint.json
```

خروجی `db_matches_signed_checkpoint=True` به معنی همان وضعیت دیتابیس در لحظه صدور checkpoint است. اگر رویداد جدید معتبر ثبت شود، وضعیت فعلی با نقطه کنترل قبلی متفاوت می‌شود و مقدار False صحیح است؛ باید checkpoint جدید صادر و checkpoint قبلی حفظ شود. بدون حفظ **مستقل و مطمئن کلید عمومی و checkpoint**، مهاجم صاحب سیستم می‌تواند کلید و شواهد را جایگزین کند. این نه امضای الکترونیکی مهندس حرفه‌ای است، نه جایگزین KMS/Immutable Storage و ممیزی امنیت تولید.
