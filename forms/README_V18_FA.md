# CMT Intelligence OS v1.8 — لایه ورود داده و کنترل منبع

این نسخه از چهار گروه فرم میدانی الهام گرفته است. **هیچ‌کدام از عکس‌های GET، نام کارکنان، شماره پروژه‌ها، یا مقادیر واقعی ثبت‌شده در آن عکس‌ها در این فایل‌ها وجود ندارند.** این کد با نمونه ساختگی قابل اجراست.

## آنچه پیاده‌سازی شده است

- **دیکشنری ۴ نوع فرم**: گزارش روزانه، گزارش بتن/سیلندر، برگه چندصفحه‌ای تراکم خاک، مشاهده میلگرد (`forms/field_dictionary_v18.json`).
- **قالب ساختاری ثبت پیشنهادی AI یا رونوشت انسانی**، با شناسه عکس/صفحه (`evidence_ref`)، منشأ پیشنهاد (`origin`)، مقدار و وضعیت بازبینی (`reviewed`, `reviewer_ref`). نمونه JSON Schema نیز اضافه شده است.
- **صف بازبینی سخت‌گیرانه**: هر فیلد نامعتبر/بدون شاهد/بدون تأیید انسانی مانع پیشرفت به کنترل بین‌فرمی می‌شود. امتیاز اطمینان مدل به‌تنهایی هرگز جای تأیید انسان را نمی‌گیرد. امضای بازبین در مثال، یک *برچسب شبیه‌سازی* است و به معنی هویت‌سنجی واقعی نیست.
- **لایه سازگاری با خروجی پیشنهادی AI قبلی** (soil/concrete): `legacy_ai_adapter_v18.py` بدون حدس‌زدن فیلدهای غایب، خروجی مدل را به حالت «تأییدنشده» تبدیل می‌کند.
- **میزکار انگلیسی و آفلاین** در `forms/Field_Capture_Review_v18.html`: پنج سند و ۵۹ مقدار ساختگی، یک فیلد تأییدنشده، و دو مغایرت ریاضی با قابلیت ویرایش، علامت‌گذاری برای بازبینی و خروجی JSON؛ هیچ درخواست اینترنتی انجام نمی‌دهد.
- **موتور کنترل بین‌فرمی قبلی** (`forms/form_engine.py`): صفحه‌های تکراری یا گمشده، پروژه ناهماهنگ، تعداد ردیف تست، و بررسی تقریبی خشک/تر و درصد تراکم. این مقایسه، تصمیم قبولی/مردودی مصالح نیست.

## کارهایی که هنوز انجام نشده است

- خواندن خودکار تصویر این چهار فرم با دقتِ اندازه‌گیری‌شده روی فرم‌های واقعی، یا اتصال مستقیم خروجی OCR جدید به سرویس AI؛ تنها آداپتور برای *خروجی AI فعلی* تهیه شده است.
- تأیید مهندسی روش‌ها، ASTM/AASHTO یا تطبیق با معیار پروژه، امضای مهندس، و تأیید استقلال بازبین.
- اتصال API / Import به ElmTree، یا هرگونه استفاده از داده‌های خصوصی GET. هیچ حساب یا مجوزی دریافت نشده است.
- پایگاه داده امن سازمانی، مدیریت دسترسی، کنترل مجوز شرکت و ممیزی ثالث.

## شروع سریع

فایل `forms/Field_Capture_Review_v18.html` را با مرورگر باز کنید. یک فیلد با وضعیت `Pending` نمایش داده می‌شود. پس از *بازبینی نمایشی* با تیک‌زدن، دکمه `Export staged JSON` را بزنید. برای کنترل کامل عددی و بین‌فرمی، روی کامپیوتری که Python 3.11+ دارد:

```bash
python -m forms.capture_v18 forms/examples/SYNTHETIC_CAPTURE_PENDING_V18.json \
  --output /tmp/cmt_pending.json
python -m forms.capture_v18 forms/examples/SYNTHETIC_CAPTURE_REVIEWED_V18.json \
  --output /tmp/cmt_reviewed.json
python -m pytest -q tests/test_capture_v18.py
```

در حالت Pending هیچ کنترلی که به تأیید همگانی نیاز دارد اجرا نمی‌شود؛ در مثالِ Reviewed، دو مغایرت حسابی پرچم می‌خورند. آستانه‌های QA مربوط به نمونه‌اند، نه تلورانس‌های مورد تأیید مهندس پروژه.

## اتصال خروجی مدل قبلی به قالب بازبینی

```bash
python -m forms.legacy_ai_adapter_v18 path/to/SYNTHETIC_AI_PROPOSAL.json \
 --type density_sheet --source-id SYN-DENS-01 \
 --project-key SYN-PROJECT --work-date 2026-10-20 \
 --output /tmp/SYNTHETIC_UNVERIFIED.json
```

به‌دلیل ناقص‌بودن اطلاعات مدل فعلی، این خروجی فقط پیش‌نویس است؛ فیلدها و متادیتای مفقود باید از اصل مجاز و توسط فرد مجاز تکمیل و بازبینی شوند. این ابزار داده‌ای به ElmTree ارسال نمی‌کند.

## محرمانگی و انتشار عمومی

وجود عکس در گفتگو به‌معنای دریافت مجوز کتبی از GET برای استفاده خارج از شرکت نیست. تنها فایل‌های **ساختگی** این بسته برای انتشار عمومی در نظر گرفته شده‌اند. نام شخص، شماره پروژه، عکس واقعی، اطلاعات دستگاه و مدارک داخلی شرکت را به GitHub عمومی ارسال نکنید. هرگونه آزمون واقعی باید با مجوز شرکت و حفاظت از داده‌ها انجام شود.
